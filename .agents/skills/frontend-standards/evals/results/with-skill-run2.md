## Rule text I found unclear or missing

- Case 02: the rule does not say whether a small task on an under-limit file must carry out an extraction the two questions earn, or only may. Limit clause 3 grants "a focused change without restructuring" to over-limit files only, which reads as more leniency for the worse file.
- Case 13: "the file that owns the state" is not defined for a context/provider split (file with the reducer vs. file with `useReducer`), and the rule does not say whether the consolidated file keeps its name.
- Case 13: no guidance on whether a data-fetching hook joins a consolidation, given "Data access and mutations colocate inside their runtime boundary" is a separate placement instruction.
- Case 11: `downloadBlob` is a DOM side effect, not a pure function; the "Business logic" paragraph covers pure functions only, so placement of small browser helpers is by analogy.
- Clause 3 "the size is reported" does not say where or in what form.
- Naming of an extracted file is not covered (chose `note-editor.tsx`, `doc-editor.tsx`, `profile-export.ts`).
