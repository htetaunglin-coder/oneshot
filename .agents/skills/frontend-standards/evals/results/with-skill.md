## Rule text I found unclear or missing

- Case 02: the rule earns an extraction with a sentence and "one consumer is enough", but it does not say whether an earned extraction is executed inside a small unrelated task on an under-limit file, or only reported (file-size rule 3 says "report, split when restructuring is inside the task" for over-limit files only).
- Cases 02 vs 09: as written, an over-limit file (09) gets less restructuring than an under-limit file with the same shape (02), because rule 3 forbids restructuring only above the limit. That reads backwards and the rule does not reconcile it.
- Case 11: the business-logic sentence keys only on "a second file calls them"; it does not say whether 150 lines of pure, JSX-free functions inside a component file is itself a nameable problem ("the page stops reading top to bottom").
- Case 13: the rule says to consolidate but not which existing file or name absorbs the others, nor whether a data-access hook with a different reason to change (`useSearchResults`) is kept out of the consolidation.
- Case 07: no guidance on where search-param parsing and defaults live (route file vs a prop default on the server component).
- Case 08: no statement of precedence when the task mandates a file path the rule would not choose (a once-used sub-component in its own file).
- Case 12: "dedicated static-data files are exempt" does not say whether a hand-written decorative SVG component file counts; did not matter at 980 lines but would at 1,001.
- Case 03: the shared scope names `src/lib` but gives no naming or sub-folder guidance (`src/lib/discount.ts` vs `src/lib/pricing/discount.ts`).
